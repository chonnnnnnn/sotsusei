# README
## 1. サービス概要
訪れた飲食店に対し「次回リピートしたいか」をワンタップで記録・確認できるアプリです。\
投稿項目を極限までシンプルにし、記録の負担を軽減。\
過去の自分の「好み・苦手」をサクッと参照することで、外食時の「また店選びで失敗した」という後悔をなくします。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
外食した際に以前利用したお店の味や感想を思い出せないことが度々ありました。\
「あまり好みではなかったな」と思った店でも時間が経つと忘れてしまい、再び訪れて同じ後悔を繰り返してしまうことがありました。せっかくの時間とお金を使う外食だからこそ、後悔なく楽しみたいと思い企画しました。


### 2-2. なぜそれが「気になった」のか
パートナーができ外食の機会が増えたことで、身近なチェーン店や定食屋などを利用する機会が増えました。\
強烈な印象があるお店は覚えていますが、「この店、味どうだっけ？」と思いながら入店し、やはり好みではなかった時に残念な気持ちになりました。\
楽しみな外食の時間だからこそ、こうした「些細な失敗」をなくしたいと感じたからです。

---

## 3. 課題の整理

### 3-1. 表に見えている困りごと
- 過去に行ったお店の評価を忘れてしまう
- 前も失敗したのにまた来てしまった」と外食後に後悔する
- 既存のグルメアプリは入力項目が多く、記録を続けるのが面倒になる


---

### 3-2. 本当に解決したい課題は何か

**面倒な記録ハードルを無くし、過去の自分の評価を即座に参照できるようにすることで、外食時の「店選びの後悔」をゼロにすること**

- **記録のハードルを低くする**\
　そもそも投稿を手間に感じてしまうと評価するためのデータが増えないので、投稿の大部分をボタンで簡素にすることにより投稿のハードルを下げ、継続しやすくする

- **過去に訪れた飲食店に行く際の「店選びの後悔」をゼロにすること**\
　・時間とお金の無駄遣いに感じ、失敗した時に残念な気持ちになるため
　・楽しみにしていた外食の時間が、後悔の時間に変わってしまうため
　・記録を残せば防げるのに、既存ツールは入力が面倒で記録習慣が続かないため

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー
- **年齢：** 20代後半〜30代社会人
- **理由：** パートナーや友人との日常的な外食機会が増え、外食の質（満足度）を重視し始める年代だから。

- **生活・状況：** パートナーや身近な人と普段使いのお店（定食屋、居酒屋、カフェ等）によく行く人。
- **理由：** 「とっておきのお店」ではなく「日常的なお店」ほど記憶が曖昧になり、後悔が発生しやすいため。

- **環境：** 細かい日記や長文レビューを書くのは苦手だが、失敗は避けたいと考えている人。
- **理由：** 1タップで完結する評価（リピートしたい/したくない）であれば習慣化できるため。

---

### 4-2. 自分とユーザーの距離
自分自身（および身近なパートナー）
→ まさに自分自身が「お店の記憶を忘れて再訪し後悔する」という体験を繰り返しており、一番の当事者だから。


### 4-3. 実際に使われる可能性について(需要・存在確認)
現在は「何も記録せず記憶に頼る」か「メモ帳アプリ」を使っているが、検索性や入力の手間で置き換えられていないため、1タップ完結の本アプリに置き換える価値がある。

### 5-2. それでも自分が作りたい理由
既存アプリやSNSは「他人に見せるための映える記録」や「詳細なレビュー」を求めるものが多く、記録するのが負担になっていました。また、「結局、自分はここをリピートしたいのか？」という結論が直感的にわかりにくいと感じていました。

### 5-3. 差別化を「体験価値」で表現する
- **私のアプリの差別化ポイント：**
「グルメ記録が続かない面倒くさがりな人が、店の前で1秒開くだけで『今日ここに入るべきか』を即断できる体験」



## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化
- **行動の変化：** 
外食後に1タップで判定を記録する習慣がつき、店選びの際に過去の自分判定をサクッと確認できるようになる。
- **気持ちの変化：**
 「また失敗した…」という後悔がなくなり、外食の時間を100%楽しめるようになる。



### 6-2. 価値を一文で表す
「過去の記憶に頼りがちな人が、1タップの記録で外食の失敗をゼロにできるサービス」

## 8. このアプリの懸念点とその対策
### 懸念点①
- 何が問題になりそうか：\
  機能がシンプルすぎて継続利用のモチベーションが落ちる
- なぜそう思うか：\
  記録するだけの単調な操作に飽きてしまう可能性があるため
- そのために考えている対策：\
  今後の開発としてマップ連携を実装し、「自分だけのグルメマップが埋まっていく楽しさ（ビジュアル化）」を提供する


### 懸念点②
- 何が問題になりそうか：\
  Webアプリのため、アクセスハードルがある
- なぜそう思うか：\
  ホーム画面からワンタップで開けるスマホアプリの方が日常使いされやすいため
- そのために考えている対策：\
  ホーム画面追加の導入を検討し、Webでありながらアプリライクに起動できる工夫をする

### 10-3.キャッチアップ不足の懸念

キャッチアップ不足の段階では以下の懸念点があります。
1. **完成までのハードルが高い**
使用する言語やフレームワークが異なるため、キャッチアップにかかる時間は個人差があるものの、一定の時間を要することが予想されます。

2. **Issueの見積もりが難しい**
「どこまで理解していて、何が分からないのか」「調査にかかる時間」などが不明瞭な場合、開発期間内に完了することが難しくなってしまいます。

3. **技術のキャッチアップについて**
技術への理解不足から調べても理解できず、制作が止まってしまうことが不安です。コミュニティーの仲間や技術面談を駆使して長時間制作が止まることないように工夫していきます。
